This is more informative than it looks. A single analysis finding nothing tells you little, because a different set of choices might well have found something. Here every reasonable set of choices was tried, and none produced a result that survived. That is a much stronger statement than one null p-value.

Two things it does not mean: that the groups are biologically identical, and that the tool failed. The usual explanation is that the study cannot settle the question at this size or sparsity.

Statistical details for this taxon p-value, adjusted p-value, effect and direction per specification

One row per specification plotted above. The {{ dfn('p_value', 'p-value') }} is the test's own; the {{ dfn('q_value', 'adjusted p-value') }} is after multiple-testing correction within that specification; the effect is the log2 fold change of mean relative abundance ({{ dataset.group_b }} relative to {{ dataset.group_a }}). Each test's native statistic (for example Wilcoxon's rank statistic, or a model coefficient) is the effect_native column of the full results export.

{% call callout('blue', 'Reading the effect axis') %}

The effect plotted here is computed from the abundance table itself — the log2 ratio of mean relative abundance between your two groups — and not from any model. So it is the same number whichever statistical test produced the point, and it does not move when an analysis adjusts for a covariate. That means this axis cannot show you covariate-driven instability: do not read a flat effect axis as evidence that adjustment does not matter.

Learn more

Measured directly on this build, the plotted effect's spread across 32 different covariate-adjustment sets is exactly zero, while the linear model's own coefficient for the same taxon moves with a standard deviation of 0.65. One common scale is deliberate: it lets every method share an axis. Where adjustment matters, it shows up in colour, as points changing significance, and in each method's own native statistic in the downloads. Treat the plotted effect as a common yardstick, not as a model coefficient you could quote from a regression table.

Before you report any of this

{% call callout('red', 'Important interpretation') %}
  • Robust to analytical choice is not biologically real. Confounding, contamination and batch effects survive every analysis intact, and nothing here is causal.
  • The percentages are not probabilities. The analyses are re-analyses of the same samples: “significant in 86%” measures how much the conclusion depends on your choices, not 86 replications and not a chance that the difference is real.
  • A label ignores magnitude. Read the typical effect beside it: a ROBUST taxon can have a difference too small to matter.
{% endcall %}

What a tier deliberately leaves out

Magnitude. A tier is built from two numbers — how often a taxon was significant and how often the direction agreed. Effect size is not one of them, so a ROBUST taxon can have a difference far too small to care about.

Independence. The analyses behind a tier are re-analyses of the same samples. "Significant in 86%" is not a p-value, not a probability, and not 86 replications.

Which choice was responsible. The tier says the answer moved, not what moved it. Open a taxon, or the curve above, to see that.

Causation, and biology. A difference that survives every analytical choice is still an association, and statistical stability is not importance.

Exactly what produced these numbers

Everything needed to reproduce this run is recorded in the run manifest — a single JSON file, also included in the results bundle as manifest.json. It holds:

  • the version of MicroVerse and of every scientific dependency that ran;
  • every random seed, including the rarefaction draws, which are what make the subsampling reproducible rather than merely repeatable;
  • the full grid accounting — enumerated, pruned with reasons, valid, fitted;
  • the dataset's dimensions and a fingerprint of the table itself, so you can confirm a later run used the same input;
  • the attribution diagnostics behind the grade shown above;
  • the validation record each claim on this page is read from.

The same content is available as JSON at /api/jobs/{{ token }}/results under manifest.
