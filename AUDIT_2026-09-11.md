# Section B — issues found independently

## 41. An attribution interval that excludes its own point estimate — **P1**

`results.html:146` prints `share` beside `result.interval(fork)`. The two come from
different estimators: `attribution.py:528-531` sets `chosen = mixed` (MixedLM) when it
converges, while `bootstrap_intervals` (`attribution.py:405-412`) documents that it uses
the `within` estimator *by design*, because MixedLM fails on some draws. Observed live:
**DA method 71.6%, interval 19–67**. The interval is not an interval for the number it sits
next to. Given the sensitivity analysis already found the estimators agree in only 8 of 17
cohorts, this will recur.

## 44. ANCOM-BC's p-values are anti-conservative in the tail — **P1, scientific**

Null simulation, no group difference by construction, 25 per group, ~4,000 tests per block,
four independent seed blocks, with Wilcoxon on the *same* datasets as control:

| nominal | ANCOM-BC | Wilcoxon (control) |
|---|---|---|
| 0.05 | 0.044 – 0.045 | 0.039 – 0.055 ✓ |
| 0.01 | **0.024 – 0.030** (2.4–3.0×) | 0.004 – 0.007 ✓ |
| 0.001 | **0.0157 – 0.0167** (≈16×) | — |

Stable across every block. Wilcoxon being correct on identical data rules out the
simulation. This matters because BH correction operates precisely on that tail, so
ANCOM-BC specifications will contribute excess false positives to `frac_significant` and
therefore to the tiers.

**Scope, stated fairly.** ANCOM-BC does not run in Quick mode (`grid.py:126` enumerates
`ELEMENTARY_METHODS` only), and both the tier validation (`tier_validation.py:306`, `--mode`
defaults to `quick`) and the real-data study (`real_data_study.py:60`) ran Quick. **The
empirical tier validation is therefore not contaminated.** Impact is confined to Full and
covariate mode. It is also possible the R package behaves identically — the point is that
this was never checked, and the R comparison that exists covers estimates, not calibration.

## 45. One NaN p-value silently voids an entire specification — **P2, latent**

`fdr.adjust` uses `np.minimum.accumulate` over the reversed sorted vector. A single NaN
propagates backwards through **every** adjusted p-value:

```
adjust([0.001, 0.02, 0.04, nan, nan], "bh")  ->  [nan nan nan nan nan]
adjust([0.001, 0.02, 0.04],          "bh")  ->  [0.003 0.03 0.04]
```

Every taxon in that specification then tests `nan <= threshold` → False. No error, no
recorded failure, and the specification still counts toward `n_specs_tested`, dragging
`frac_significant` down and potentially demoting a tier.

**Currently unreachable, and deliberately so.** All seven methods were probed against
all-zero, constant and singleton taxa and none emitted a NaN, and `preprocess.py:90` removes
all-zero taxa even at the 0% threshold via `& (prevalence > 0)`. This is a latent fragility
with no present symptom, not a live bug.

### P1-1 · Attribution interval excludes its point estimate
- **Where** `app/core/attribution.py:405-412` and `528-531`; `results.html:146`
- **Why** An interval that does not contain its own estimate is not an interval, and it
  appears beside a number the page asks the reader to trust.
- **Fix** Either bootstrap the same estimator that produced the displayed share, or label
  the interval as belonging to the `within` estimator and show that estimator's point value
  alongside it. Do not silently pick whichever looks tighter.
- **Accept** Every rendered bar satisfies `low <= share <= high`, asserted in a test over
  all three demos.

### P1-2 · ANCOM-BC tail calibration
- **Where** `app/core/methods/ancombc.py`; evidence in finding 44
- **Why** BH operates on the tail; a 16× excess at p ≤ 0.001 propagates into
  `frac_significant` and the tiers in Full and covariate mode.
- **Fix** First establish whether R's ANCOMBC shows the same profile on the same simulated
  nulls — if it does, this is inherited and belongs in the documented limitations, not in a
  patch. If it does not, the divergence is in the Wald statistic or the bias-corrected SE.
  Do not adjust p-values to hit a target rate.
- **Accept** A reference check in `tests/reference/` records the null rejection rate at
  0.05/0.01/0.001 for both implementations, and either `REVIEWING.md` states the inherited
  limitation or the divergence is closed and asserted.
